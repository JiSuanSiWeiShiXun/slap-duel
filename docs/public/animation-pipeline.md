# 可复用的角色、绑定与双人动作管线

这套流程用于把新角色接入《掌上对决》：先验证模型能正确变形，再重定向动作，最后验证两人配合及真实游戏输入。可复用的是分层检查方法、输入输出契约和对照办法；旧角色的顶点补丁、骨轴、接触坐标需要重新标定。

配套入口：[新角色接入记录模板](animation-intake-template.md) · [资产来源与引擎约定](assets.md)。本机项目内另有流程技能与私人实验记录；本文及模板可独立使用，不依赖这些本地文件。

## 换一个模型，哪些能直接复用

动捕动作是可重复使用的输入资产，重定向是让该动作适合另一套绑定的过程。不是所有绑了骨的模型都能直接播放同一份骨动画，也不是换人物就必须重新动捕。

| 新模型情况 | 动作复用方式 | 仍要验证 |
|---|---|---|
| 骨层级、真实 bind/rest、局部轴和动画接口完全兼容，比例相近 | 可尝试直接共享动画，先做代表动作小样 | 新蒙皮/衣服变形、实际导入、双方接触；同骨名或相近外形不等于接口兼容 |
| 都是人形，但骨名、层级、参考姿、骨轴或比例不同 | 建立源→目标映射和姿态校准，重定向后修整 | 肘腕连续性、骨长、脚部、掌颊及全路径接触 |
| 模型没有有效骨架或蒙皮 | 先建骨架并完成蒙皮/标准姿，再接动作 | 静态造型精细不证明模型可变形 |
| 四足、多手臂或其他结构差异明显 | 另定语义链和动作规范；只复用适用部分，必要时重新制作 | 现有人形流程和脚本未覆盖该结构，不承诺通用适配 |

我们的几个职场角色优先共享人形语义骨架与动作规范，各自完成蒙皮和模型 Profile；角色表现风格可另作有意变体。即使共享同一骨架，换衣服、头部大小或身体比例后，也不能自动继承旧接触结果。

## 重定向具体怎么做

两份基本输入是：**带动画的源骨架**，以及**带有效骨架/蒙皮的目标模型**。源可以是已检查的动捕，也可以是已经人工修整好的游戏动作；记录它是哪一种，不因换模型重新提交动捕。原视频用于追溯和检查源动作时保留，不是每次复用已经冻结的动作都要再次提取。

| 步骤 | 操作与保存产物 |
|---|---|
| 1. 检查源动作 | 隐藏网格看源骨线，核演员、片段、时轴、单位和根运动，标明跳变/遮挡未知段；保存源签名与审核结果。源未过不把错误带到目标。 |
| 2. 建立语义映射 | 映射骨盆、脊柱、头、左右肩/上臂/前臂/手及腿脚；额外骨逐一分类，声明 twist 分配、约束/控制骨烘焙和未映射骨策略；保存映射配置。 |
| 3. 校准参考姿与骨轴 | 统一坐标与单位，处理源 T-pose、目标 A-pose 等差异；分别保存真实 bind/rest 与用于重定向的校准姿，不为对齐动作而无记录地改蒙皮 inverse bind。保存各链校准变换和校准图。 |
| 4. 转移相对运动 | 将源相对校准姿的运动，按目标父链和坐标轴转换；保留目标自身骨长，按已声明策略适配骨盆/root位移。不能直接抄 Euler XYZ 或源骨位置；检查目标裸骨与源是否保留预期节奏和表演。 |
| 5. 修接触与形变 | 在目标上查脚滑、肘 pole、腕向、衣服；再让双方共同时轴检查护脸、来掌、另一手反掌、受击和撤手。用有界 IK、站距或动作变体修整，不以末端碰到目标代全程通过；人工层另存。 |
| 6. 固化与引擎验证 | 保存目标骨架自己的可编辑 Action，需烘焙的约束转为实际变形骨关键帧；记录关键时刻与插值。导出后按同时间比较保存源、实际导入和真实 Cocos，避免导出采样改变已验动作。 |

例如源初始手臂平举、目标初始手臂斜向下，要转移的是相对于已对齐参考姿的运动，不是把源骨角度照抄给目标。IK 只根据手/脚目标求关节姿态，不能替代合理站距、关节朝向和自然的整段轨迹。

本项目第五稿使用“静态 FBX＋原标量曲线侧车”的实验传递路径，保留目标 Action 的求值；不是一律把所有动作重新均匀采样进 FBX。采用何种烘焙/导出方式，以实际引擎保真验收为准。

## 映射和标定配置能复用多久

首次对一个源骨架与目标骨架组合建立映射、校准和根运动策略后，可给**相同源骨架规范、相同目标绑定**的其他动作复用。每个新动作仍要检查极限姿态、接触、时序和导入；配置复用不等于每段动画自动合格。来源若也是另一套骨架，需新映射/校准，不能只凭“都是人形”沿用。

配置身份至少绑定源/目标骨链与 rest/轴签名、单位、版本和目标运行骨架。骨层级、轴、rest、比例或根运动合同改变时重新标定；只改外观但改了衣物/权重时重新做变形测试；掌面、脸颊或体型改变时重新标定接触 Profile 并回归配对。新拓扑不能沿用旧顶点索引补丁，按顶点/三角定位的表面锚点也要重新建立。

当前 `retarget-motion.py` 等脚本仍固定 manager 模型路径、部分骨名/对象名、旧输入 hash 与接触参数。模板提供的是把这些依赖拆为每角色配置的合同；尚未实现读取任意 Profile 即可一键导入新模型的通用工具。旧模型小样的原命令和签名检查保持，给新模型建立适配器与独立输出，不通过放宽旧门槛伪装适配成功。

## 开始一次新模型接入

在项目根建立一个独立、被 Git 忽略的试验目录。目录名每次不同，原始文件保留只读副本，不覆盖已验收产物。

```powershell
New-Item -ItemType Directory -Path game/local/character-intake/example-character-001
```

从[模板](animation-intake-template.md)复制 JSON 到该目录的 `intake.json`。先填写模型/动作来源与许可、文件 SHA256、实际工具版本、单位/朝向、骨架和 rest pose，再执行下表。检查器、渲染、作者源和实际引擎分别保存结果；模板本身不证明任何验收通过。私人素材、服务回执和凭据留在忽略目录，发布前另做许可与公开树检查。

## 八步交付合同

| 步骤 | 输入与依赖 | 操作 | 输出与过关标准 | 失败回溯 |
|---|---|---|---|---|
| 1. 骨架规范 | 人设、体型/服装、目标动作、引擎蒙皮能力 | 确认单位、朝向、rest pose、骨名/父链、肩肘腕 pivot、骨长轴、肘 pole、掌心/手背与脸颊语义；确认双方比例下的可达范围 | 骨架/接触规范及可视化标记。左右、长轴和真实表面含义明确 | 比例不可达先改站距或动作设计；不要靠伸长骨或折腕补偿 |
| 2. 模型与关节拓扑 | 骨架规范、可编辑网格、服装层次 | 检查肩腋、肘、腕、颈、膝的边环、极点、细长面及衣片连接；保留 UV/材质身份 | 局部线框与中性姿。变形区域有适合目标动作的结构；全身面数只记录身份 | 不凭总面数判质量；看到骨反折应转查动作层 |
| 3. 绑定蒙皮 | 模型、真实 bind/rest、目标蒙皮方式 | 按实际皮肤与衣片连通关系配权；检查非负/归一化/未加权点、影响数和 bind 一致性 | 可编辑绑定源、权重/bind 摘要。数值合法且没有明显中性裂口或衣片错随 | 先查骨/衣片归属与权重；合法权重仍可能变形难看 |
| 4. 标准姿验收 | 固定模型、骨架、独立标准姿及一条固定 Action | 分别测中性、屈肘、抬臂、前臂转、独立腕摆、转头和下肢；骨线/蒙皮/线框分看，正侧后比较；重开源文件核验 | 保存源、标准姿图、目标动作最差姿对照、变更日志。看得到改善且没有新增缺陷后冻结模型/绑定 | 同骨姿仅换权重；仍不足再做局部拓扑 A/B。不要同时重新求 IK 后宣称是加面收益 |
| 5. 动捕与重定向 | 冻结源骨架/动作（动捕或已修整 Action）、如有原片、冻结目标绑定 | 动捕输入先比原片与未经修改的源骨架；复用 Action 核既有来源。再做源→目标语义映射、rest 校准、骨轴/比例换算、肘向/腕向连续性检查；人工调整独立另存 | 可用来源/源骨架/目标骨架/蒙皮同时间比较、映射表与修整记录。异常首现层可定位 | 源已错查遮挡/动捕估计/读取；源正常而目标错查映射、rest 与约束 |
| 6. 双人成对修整 | 两个模型及各自绑定、同一事件时轴、真实掌/颊表面 | 共同调整站距、来掌→架挡→另一手反掌→受击→收招；核四臂、身体、手头和脚，检查接触前后整条路径及速度 | 完整原速主视和反侧、关键姿、接触/穿插/关节与速度报告。攻防因果可读，指定采样域内没有未解释的异常 | 单人自然不能代双人通过；端点贴合不代表整路可行，掌背含义也不能靠单个三角法线猜 |
| 7. 同源实际 Cocos | 重开并冻结的作者源、实际导出数据、真实 Creator 导入与 `.meta` | 比作者源→导出→实际导入的相同时间骨世界矩阵与蒙皮；再在原生运行检查播放/暂停/逐帧/显示/镜头 | 构建身份、逐层误差报告、实际运行证据。作者源符合预期且引擎传递在已声明容差内 | 作者正常而游戏错，查坐标、插值、关键时刻、导入和运行时，先不要重编作者动作掩盖传递错误 |
| 8. 任意输入与衔接 | 固定动作已过、普通攻击/格挡/受击/恢复动作、战斗规则 | 测左右站位、两种攻击、早/晚防守、最早再攻、打断/重开及后台恢复；检查入口/出口位置和速度连续性 | 实际输入、事件/HP 与完整过渡录像。规则时间不被动画改变；无瞬跳、额外伤害或隐藏输入锁 | 固定配对片通过不能继承到自由对局；返回动作兼容与过渡层，不以推迟判定遮住问题 |

当前项目制作基线为 Blender 4.5.14 LTS、Cocos Creator 3.8.8；新执行仍须记录实际版本。标准姿角度、采样密度、误差容差和权重影响上限，按新角色、导出路径及引擎能力明确填写，不能从旧样本直接认定适用。

新骨架的每根骨还要分类：变形骨、控制/IK 骨、twist 骨、面部/服装骨及末端/未用骨。Profile 记录骨链映射与额外骨策略，例如保留 rest、继承、分配扭转、由独立系统驱动或烘焙到变形骨；不默认未映射骨可以删除。先决定保留原骨架还是另制运行骨架，列出实际导出的变形骨、bind 与运行能力合同。把旧检查器的“29”改成“70”不能证明新70骨模型已适配。

## 怎样定位“反关节”

按相同时间逐层比较，找到**最先出现异常的层**。先定位，再修改。

| 观察 | 优先检查 | 最小对照 |
|---|---|---|
| 原片关节被遮挡，源骨架跳变 | 原片信息、动捕估计或源数据读取 | 对齐原片与未改源骨架，记录可见段和不确定段 |
| 源骨架正常，目标骨线反折 | rest、骨轴、父链、肘 pole、比例与重定向 | 冻结源，只改一个映射/校准因素 |
| 目标骨线正常，袖口或皮肤塌尖 | 蒙皮权重、衣片连通、局部拓扑与蒙皮方式 | 冻结 bind/Action；先 weights-only，再局部 topology 对照 |
| 两人独立正常，交互穿插 | 站距、掌/颊表面、完整四臂路径及事件时序 | 固定模型与绑定，仅调整成对编排 |
| 作者源正常，实际游戏跳变 | 导出/采样/导入、混合及状态切换 | 同时刻保存源与实际引擎比较，区分静态传递和实时过渡 |

屈肘角要由真实骨长轴与 rest 定义；local XYZ 数字不天然等于人体屈伸角。独立转 Hand 才覆盖腕摆，转 Forearm 不能替代腕测试。人体活动范围没有独立依据时，只能声明几何校准与已测姿态，不能写医学合格。

## 标准姿通过，新动作仍穿插怎么办

标准姿是基础覆盖，不能穷尽角色之后会遇到的姿态。一次新出掌试验中，十组标准姿和旧动作指定姿态在同一袖胸部位均通过，新轨迹却在接近命中的末段出现衣袖交叉；逐毫秒检查把首个坏采样定位在474ms。先看同姿骨线与蒙皮，再用肩带协同做一次动作层对照，交叉减少但没有消失。这个结果不足以宣布动捕错误，也不足以宣布旧权重普遍错误。

随后冻结该动作，只调整每个实例右袖的12个顶点，在胸与上臂两组之间有界转移权重；模型拓扑、UV、rest、bind及动作保持原样。新前缀在961个实际曲线key、逐毫秒和60Hz组成的联合采样时刻通过，并重验十组标准姿与旧动作的指定姿态。这支持该角色在**这条新轨迹中的局部蒙皮适配**，不证明全部动作、其他模型或完整自由对战已经通过。

要证明“只改了蒙皮”，不能只比较几个关键姿，或复制旧网格字段后宣称新文件不变。分别重开父版本与新保存源，实际抽取网格、UV、rest/bind、对象变换、完整命名权重、所有Action曲线及其关键帧/手柄/插值/修改器、动作绑定/NLA/约束；比较声明覆盖域的差异，只有批准的权重变化才能放行。明确排除求值耗时等瞬时字段，列出未支持字段。曲线坐标相同但手柄或约束不同，仍可能改变实际动作。

这个补丁产生新的模型/蒙皮版本。其余动作即使骨轨不变，也须按新模型身份重验，接触锚点、导出蒙皮和引擎验证不能沿用旧版本结论。保留旧版本作对照，不能因为局部修复通过便关闭整个动作任务。

## 接触与速度报告各能证明什么

掌中心距离和法线相对只描述两个局部标记。一份试件中，两掌中心相隔约3mm、法线相对，完整手掌、拇指和手指仍发生交叉，因而端点失败。应先明确真正接挡的表面区域，例如掌根与来掌近腕或远端前臂，再检查完整手形、四臂和身体；接触点成立不代表接触区域或来去路径成立，三角交叉对数也不是穿深。

真实表面锚点还可能受多根骨共同影响。一份普通来掌试件中，掌片三个顶点分别带有不同比例的前臂权重；保持 Hand 世界矩阵不变、只换肘位，实际掌片仍移动并离开接触范围。求解时应逐点使用目标引擎的蒙皮算法，把关节位置、骨长和实际皮肤接触一起重算，不能把整只手视作刚体，或用平均手骨权重反除一次位移便宣布接触保持。

掌面法线也没有确定手指方向。先用真实 Fingers−Hand 长轴确认手指指向，再按动作语义确定掌面内的朝向；肩到脸的投影只是一个设计选择，不能自动成为不可改的约束。先求腕角、正确肘弯侧、前臂旋转等约束的交集，再从中选择自然肘位，避免只满足腕角却选成反肘。本次改用手指向上的语义并联合求解真实蒙皮后，保存复开的单个端点通过原静态门；这个结论仍不包含完整出掌、接挡、反击或引擎运行。

速度检查要分清必要条件与实际路径验收。两端肘位置的欧氏距离除以可用时间，是平均平移速度的必要下界；相同定义下两端姿态的最短旋转角可用于相应角速度下界。下界不超限仅表示尚未排除该端点，不能代替中间路径逐采样检查。报告必须使用同一坐标系、单位、归一化方式与时间预算，明确检查的是哪一种速度。

沿骨长轴的旋转和轴向扭转还涉及分解方法。世界骨轴在端点间做一次最短transport后得到的残余roll由端点确定，但它与逐段累计roll的关系取决于中间骨轴路径；把这一端点诊断直接除以时长，不能自动当作所有路径都必须承受的扭转下界。它只提示端点直接对齐时的轴向差；只有对明确指定的中间路径按原采样和度量实测超限，才可拒绝那条路径。不能据此声称全部3D路径不可能，也不能反过来忽略实际路径的超速。最终仍用冻结源的完整轨迹和原检查定义复验。

## 什么时候给关节增加布线

在骨线正确、权重经过受控修正后，仍出现固定的硬折角、压缩集中或无法同时保持中性与目标屈曲，才安排局部重布线实验。固定骨架、bind、Action、材质、灯光和镜头；记录新增点的权重插值办法、UV 变化和实际性能成本。新拓扑要在真实镜头原速下有可见收益，并重过导出与双人动作门。

本次旧角色基础实验中，只改权重改善了肩袖和后颈；额外增加颈环没有足够可见收益，因此未采用。这支持“先用对照判断责任层”，不能推出其他新模型无需加环。旧模型的 **3,207 顶点索引补丁**仅适用通过相同模型签名及每点旧权重检查的输入；换拓扑、顶点顺序或绑定后，必须重新求权重，不得照抄索引。

## 这次第五稿为什么值得保留

第四稿已过若干几何与传递门，但原速仍像高位拍头、绕头收手。第五稿保持模型、拓扑、UV、绑定和身体/腿部，只重新编排反击手的“胸肩侧准备→侧向背掌→短撤”，视觉结果明显改善。用户反馈为“这个结果比之前好很多了”。

这次对照说明：该缺陷的改善来自动作路径，不是增加面数；技术门通过之后，仍必须看完整原速。动作名叫 `ready` 也不能证明手真正处于正确准备位置，需看真实腕位和轮廓。

以下只记录本次样本，不能作为新角色统一标准：

| 当前样本参数 | 新模型如何处理 |
|---|---|
| 29 骨、既定 rest 与轴 | 重新记录完整骨架并建立语义映射；同骨名不等于同 bind |
| 1 秒固定片，接挡/反掌在 0.15/0.33 秒 | 分开填写作者片标记与规则事件；本游戏精准反击间隔仍由规则控制 |
| 2 微米级部分源传递门 | 属于该固定源数值保真测试；不等于自然度标准，原生运行另有声明容差 |
| 当前角色的掌/颊锚点、站距与 IK 约束 | 对新模型真实皮肤重新标定，检查左右和掌背语义 |
| 静态 FBX＋原标量曲线＋`Node.setRTS` 的实验传递路径 | 可作为已跑通方案参考；新骨架/形变特性仍需验证，普通 FBX 自动采样不等价于保留精确曲线 |

此次反馈确认了明显改善，未代替最终角色风格/力度采用。第五稿固定配对已实际进入 Cocos 实验；任意时机防守的衔接仍未通过。视觉预演、手机性能和完整 Spike 也不能由这次反馈一并关闭。

## 每次迭代必须留下什么

每次只提出一个可验证假设，例如“同骨姿只修袖子权重是否能去掉尖角”。保留父版本身份、输入/输出 hash、命令与工具版本、变更范围、人工改动、失败样本及已测范围。比较画面使用相同模型、姿态/时刻、速度、镜头、光照和构图；有意改变的项单独列明。

至少交付：可编辑源、模型/骨架/rest/权重签名、源动作与映射表、双人事件表、原速主反视频、关键姿、实际引擎构建与运行证据、仍未验证项及用户原话。双人镜头应包含全身和鞋底；局部放大作为补充。不能通过裁掉脚或换遮挡镜头宣布缺陷消失。

先 1×看动作因果、准备/发力/受击/回收，再慢放查异常。数值报告负责定位和保真，原速观感负责动作可读性，真实输入负责即时性，用户试玩负责最终采用。没有实际检查的条目保持 `PENDING`；检测失败或结果未知分别记录，不改阈值或期望值把失败变成通过。

H3/LoRA 等生成视频可用于校准形象和视觉方向，不能提供实时双人碰撞或战斗裁定。可编辑模型、绑定、曲线、重定向、成对修整及 Cocos 验证才是本管线的实时交付链。手工重新编排应明确标记；没有工时对照时不宣称动捕节省了制作成本。

## 新增角色会不会产生 n(n−1) 套动作

要区分“角色重定向”与“两人配合验收”。设有 n 个角色、k 套共同动作，不允许同角色对战，攻击方/防守方身份有方向：

| 工作 | 规模与复用方式 |
|---|---|
| 每角色接入标准动作库 | 通常约 n×k 次接入与验收；先为一个角色建立 Profile，再复用共同动作，不必为每个对手重新制作整套基础动作 |
| 所有有向配对的接触与输入回归 | 最坏覆盖约 n(n−1)×k；重定向复用不能自动证明每个体型组合都自然。自动化可降低执行人力，仍需覆盖组合 |
| 加入第 n 个角色 | 新增与旧角色的 2(n−1) 个有向配对；旧模型、旧规则和共同求解逻辑不变时，不需要重新制作旧配对动作 |
| 允许同角色对战 | 有向配对为 n²；加入第 n 个角色新增 2n−1 个配对，包含自身对战 |

例如从三人扩到四人，不允许同角对战时，总有向配对由 6 增为 12，新增 6 个；并不意味着原有 6 个配对都要重做。若修改共用求解、动作库或骨架合同，则按影响范围重跑旧配对回归。这些是工作量模型，不是当前已实现自动化的承诺。

面向扩角色，建议采用标准语义骨架与动作库，每角色单独记录 Profile：骨名映射、rest/骨轴、身体比例、掌/颊表面锚点、肘 pole、可达域及允许的修整范围。双人共用事件时序，在有限范围内做站位和 IK 调整；极端体型或特殊服装保留专用动作变体。当前尚未交付通吃新模型的成对求解器，这一设计需要在接入下一模型时验证，无需因此迁移游戏引擎。

IK 末端对齐不是自然动作保证。任何配对仍须检查完整接近/离开路径、四臂与身体穿插、速度和入退出衔接。超出可达域时，优先调整站距、准备姿态或专用变体；仍不可行则明确限制该配对，不靠硬拉关节或延迟规则事件补洞。根节点对齐只能处理整体位置/朝向，不能代替双人全身接触求解。

这些技术可参照 Epic 官方的 [IK Rig Retargeting](https://dev.epicgames.com/documentation/en-us/unreal-engine/ik-rig-animation-retargeting-in-unreal-engine)（骨链映射、不同骨架比例与 IK 接触）及 [Motion Warping](https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-warping-in-unreal-engine)（指定窗口内的根运动目标对齐）。2026-11-11 核读；它们支持上述技术区分，不表示本项目已有 UE 功能或通用双人求解器。
